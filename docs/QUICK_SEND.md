# PC 바로가기로 바로 보내기 — 설계안

> 상태: **승인 (2026-11-27) · 구현 v0.61.0** — 결정은 `DECISIONS.md` M-78.
> 결정(사용자): Threads 전용 기능이 아니라 일반 기능으로 만든다. 휴대폰은 "확인 없이 보낼 범위", PC는 "바로 클립보드에 넣을 범위"를 설정으로 고르고, Threads는 PC 범위의 기본 사이트 목록이 된다. **PC 브라우저로 열기는 나중**(§9). 실패하면 알림 + [다시 보내기](쌓아 두었다 자동 전송은 하지 않음), 이번엔 클립보드를 거친다(Archiver 쪽 딥 링크는 나중).
> 바탕: M-62(클립보드 텍스트 보내기, 기기·PC 쌍 합의 키), M-67(공유 센터·PC 바로가기), M-68(Homebase 토스트·`homebase:` 링크), M-70(주고받은 클립보드 이력), [`CLIPBOARD_SHARE.md`](CLIPBOARD_SHARE.md) §2(휴대폰 → PC 자동 동기화는 Android가 막음).

## 1. 요구와 성공 기준

**요구(사용자)**: 휴대폰에서 Threads를 보다가 재미있는 글을 PC로 던지면, PC의 Threads Archiver가 알아서 받게 하고 싶다. Archiver는 PC 클립보드에 Threads 링크가 올라오면 감지해 다운로드한다. Homebase PC는 원하는 것만 클립보드에 올리고, 받을 준비가 됐다는 표시를 보여야 한다. 이를 Threads 전용이 아니라 옵션을 고를 수 있는 일반 기능으로 만든다.

**출발점은 "복사"가 아니라 "공유"다.** Android 10부터는 화면 맨 앞의 앱이나 기본 키보드만 클립보드를 읽을 수 있어, Homebase가 뒤에서 복사를 알아챌 수 없다(CLIPBOARD_SHARE.md §2). Threads의 `링크 복사`는 공유 메뉴 안에 있으므로, 같은 메뉴에서 Homebase의 PC 바로가기를 누르게 하면 누르는 횟수가 거의 같다.

**성공 기준**
- Threads 공유 → PC 바로가기 "집 PC"를 누르면 확인 화면 없이 보내지고, 몇 초 안에 PC의 Archiver가 그 글을 받기 시작한다.
- 기기를 고르는 기존 공유 흐름(Homebase 아이콘 → 공유 센터 → [공유 시작])과 그 결과(바로 클립보드)는 그대로다.
- PC는 바로가기로 바로 온 것 중 설정한 범위에 드는 것만 클립보드에 넣는다. 나머지는 클립보드를 건드리지 않고 알림으로 알려, 누르면 넣는다.
- PC 화면에서 받기 범위, 오늘 받은 수, 마지막 시각, (Threads가 범위에 있으면) Archiver 실행 여부가 보인다.
- 실패(PC에 닿지 않음, 로그인 안 됨, 클립보드 바쁨)는 휴대폰에 알림으로 남고 [다시 보내기]로 다시 보낼 수 있다.

## 2. 지금 구조에서 확인한 것

- **보내는 길은 있다.** 휴대폰 → PC 텍스트는 `POST /api/v1/clip`(봉인한 `ClipContent`, M-62) → Agent가 브리지 `clip.set`으로 트레이에 → 트레이가 클립보드에 넣고 `clip.done {id, ok}`. 받을 트레이가 없으면 409 `no_user_session`, 클립보드가 바쁘면 503 `clipboard_busy`.
- **PC 바로가기도 있다.** Android 10+ 공유 시트에 PC별 바로가기가 많이 보낸 순으로 최대 4개 뜬다(`ShareShortcuts.kt`). 지금은 누르면 그 PC가 체크된 공유 센터가 열리고 [공유 시작]을 한 번 더 누른다 — "어떤 앱이든 아무 텍스트로 이 화면을 열 수 있으니 어디로 갈지는 사용자가 정한다"(M-67).
- **Threads Archiver의 감시**(`threads-downloader/apps/desktop/src-tauri/src/watcher.rs`, v0.10.3): 0.5초마다 `GetClipboardSequenceNumber`를 보고 바뀌었을 때만 읽는다 → 0.5초 안에 두 번 바뀌면 앞의 것을 놓친다. 4,096바이트 이하 텍스트에서 `threads.com`·`threads.net`의 `/@아이디/post/<id>`·`/share/<id>`를 찾는다(글 + 링크도 받음). 한 번 실행하는 동안 이미 알린 링크는 다시 알리지 않는다. 실행 파일은 `threads-archiver-desktop.exe`. 링크를 직접 넘겨받는 입구는 없다.

## 3. 흐름

```
휴대폰 앱 ─공유─▶ 시스템 공유 시트 ─"집 PC" 바로가기─▶ ClipShareActivity (화면 없음)
   │  휴대폰 설정 범위에 들고 1분 10번 안이면
   ▼
POST /api/v1/clip   봉인 내용 {text, chars, ts, quick: true}
   ▼
Agent ─clip.set {…, quick}─▶ 트레이: PC 설정 범위에 드나?
   │   든다  → 클립보드에 넣기(바로 보낸 것끼리 1초 간격)
   │   안 든다 → 넣지 않고 토스트 [클립보드에 복사]
   ◀─clip.done {id, ok, held?, archiver?}─
   ▼
200 {schema, accepted: true, quick: true, held, archiver?}
   ▼
휴대폰 토스트 "집 PC로 보냄"            PC: Archiver가 클립보드에서 감지 → 다운로드
```

## 4. 휴대폰

### 4.1 설정

설정 › 공유에 **"PC 바로가기로 공유하면 바로 보내기"** — `끔`(기본) / `링크만` / `링크와 텍스트`. 켤 때 설명 한 줄: "공유 메뉴의 PC 바로가기를 누르면 확인 화면 없이 보냅니다. 다른 앱도 이 바로가기로 보낼 수 있어 PC에서 받을 범위를 함께 정해 두세요."

- `링크만`: 텍스트에 `http://`·`https://` 주소가 하나 이상 있을 때.
- `링크와 텍스트`: 비어 있지 않은 텍스트 모두(최대 10만 자, M-62).
- 텍스트는 **고치지 않고 그대로** 보낸다(주소만 뽑지 않음 — Archiver는 글 + 링크도 받는다).

### 4.2 바로 보내기

`ClipShareActivity`가 다음을 **모두** 만족할 때만 공유 센터를 건너뛴다. 하나라도 아니면 지금처럼 공유 센터를 연다(그 PC가 체크된 채로).
1. PC 바로가기로 열렸다(`EXTRA_SHORTCUT_ID` → 연결된 PC).
2. 파일·사진이 아닌 텍스트 공유다.
3. 설정 범위에 든다.
4. 최근 1분 동안 바로 보낸 것이 10번 미만이다.
5. 앱 알림이 켜져 있다 — 꺼져 있으면 Android가 화면이 닫힌 뒤의 결과 토스트와 실패 알림을 막아, 실패가 아무 말 없이 사라진다.

- 화면은 그리지 않는다(투명). 보내는 동안만 떠 있고 끝나면 닫는다.
- 보내기는 공유 센터와 같은 코드(키 합의 재시도 포함)를 쓰고, 봉인 내용에 `quick: true`를 넣는다.
- **결과**
  - 200, `held: false`: 토스트 "집 PC로 보냄". `archiver: "stopped"`면 "집 PC로 보냄 · Threads Archiver가 꺼져 있음".
  - 200, `held: true`: 토스트 "집 PC로 보냄 · PC의 받기 범위 밖이라 알림으로 받음".
  - 200인데 응답에 `quick`이 없음(옛 PC): 토스트 "집 PC로 보냄 · 클립보드에 넣음(PC를 업데이트하면 받기 범위를 씀)".
  - 실패: 알림(채널 `hb.clip`) "집 PC에 보내지 못함 — <이유>"와 [다시 보내기]·[다른 기기로]. 이유는 PC에 닿지 않음 / 로그인한 사용자 없음(409) / 클립보드가 바쁨(503) / 그 밖. [다시 보내기]는 같은 텍스트를 같은 PC로 다시 바로 보낸다(같은 결과 처리). [다른 기기로]는 그 텍스트로 공유 센터를 연다.
- **기록**: M-70 `clip-sent`(보낸 클립보드)에 지금처럼 남기고 제목에 "바로 보냄"을 붙인다. `held`면 "PC에서 알림으로 받음"도.
- 바로가기 순위(`ShareShortcuts.used`)는 지금처럼 센다.

## 5. 프로토콜

- 봉인 내용 `ClipContent`에 선택 필드 **`quick`**(bool, 거짓이면 생략)을 더한다. 봉투·키·다른 필드는 그대로다.
- **새 PC**: `quick`은 휴대폰 기기에서 온 것만 받는다 — PC 기기(그룹 링크)에서 오거나 `to`(휴대폰 ↔ 휴대폰 중계, M-67)와 함께 오면 400 `invalid_clip`. 성공 답은 200 `{schema, accepted: true, quick: true, held: bool, archiver?: "running" | "stopped"}`. `archiver`는 텍스트에 `threads.com`·`threads.net` 주소가 있을 때만 싣는다. 실패는 기존 409·503 그대로.
- **옛 PC**: `quick`을 모르니 무시하고 지금처럼 클립보드에 넣는다. 답에 `quick`이 없어 휴대폰이 알아챈다.
- **브리지**: `clip.set`에 `quick`, `clip.done`에 `held`·`archiver`(선택). 설치본은 Agent·트레이가 같이 바뀐다.
- 같은 기기·같은 id 30분 한 번(M-62)은 그대로 — `held`로 끝난 것도 기억한다(다시 보내도 알림이 두 번 뜨지 않음).

## 6. PC

### 6.1 받기 범위 (설정)

트레이 설정의 클립보드 공유 자리에 **"휴대폰에서 바로 보낸 것"** — 바로 클립보드에 넣을 범위:
- `모든 텍스트`
- `링크가 있는 것만` (텍스트에 `http(s)://` 주소)
- `지정한 사이트의 링크만` (**기본**, 목록 기본값 `threads.com`, `threads.net`)

사이트 목록은 한 줄에 하나(도메인만, 하위 도메인 포함: `www.threads.com`도 `threads.com`에 든다). `http(s)://`가 없는 `threads.com/…`처럼 사이트 이름으로 시작하는 토큰도 그 사이트 링크로 본다. 링크·사이트 판정은 UTF-8로 4,096바이트 이하인 텍스트에서만 한다(Archiver와 같은 기준, 넘으면 범위 밖). **`링크가 있는 것만`·`지정한 사이트의 링크만`이면 텍스트 전체가 아니라 맞은 첫 링크만** 넣는다(앞뒤 따옴표·괄호·문장부호를 떼고, `http` 없는 사이트 토큰은 `https://`를 붙임) — 다른 앱이 링크에 명령줄 같은 텍스트를 얹어 PC 클립보드에 몰래 넣는 것(pastejacking)을 막는다. `모든 텍스트`만 텍스트 전체를 넣는다. 저장은 사용자별 `%LOCALAPPDATA%\Homebase\quick-clip.json`(관리자 필요 없음). **이 범위는 `quick`으로 온 것에만** 쓴다 — 공유 센터에서 사람이 [공유 시작]을 누른 것은 지금처럼 바로 넣는다.

### 6.2 받기

- 범위에 들면 기존 `ClipboardShare.PutAsync`로 넣는다. 바로 보낸 것끼리는 넣은 뒤 **최소 1초** 간격을 둔다(큐 하나, 순서 유지 — Archiver가 0.5초마다 보므로). 줄에서 7초 넘게 기다린 것은 늦게 넣지 않고 "넣지 못함"으로 답한다(Agent가 `clip.done`을 10초까지 기다리므로, 늦게 넣으면 휴대폰은 실패로 알고 다시 보내 두 번 들어간다).
- 범위 밖이면 클립보드를 건드리지 않는다. Homebase 토스트(M-68) "Galaxy S24에서 받은 텍스트 — 받기 범위 밖이라 클립보드에 넣지 않았습니다"와 [클립보드에 복사]를 띄운다(텍스트 미리보기는 싣지 않고 길이만 — Windows 알림 목록에 남으므로). 보관하지 못하면(파일·잠금 실패) 버튼 없이 알리고 "넣지 못함"으로 답해 휴대폰이 [다시 보내기]를 띄운다. 버튼 링크는 `homebase://clip/copy?id=<id>`이고, 텍스트는 사용자별 `%LOCALAPPDATA%\Homebase\held-clips.dat`(DPAPI CurrentUser, 최근 20건·24시간)에 둔다. 링크에는 id만 실으므로 웹 페이지가 `homebase:` 링크로 임의 텍스트를 클립보드에 넣을 수 없다. 클릭한 실행(`--toast`)이 id로 찾아 클립보드에 넣고 그 항목을 지운다.
- **Archiver 확인**: 텍스트에 `threads.com`·`threads.net` 주소가 있으면 트레이가 자기 세션에서 `threads-archiver-desktop` 프로세스가 있는지 보고 `archiver`로 답한다. 클립보드에 넣었는데 꺼져 있으면 토스트 "Threads 링크를 받았지만 Threads Archiver가 꺼져 있습니다". 켜져 있으면 Homebase는 토스트를 띄우지 않는다(Archiver가 띄움).
- **기록**: M-70 `받은 클립보드`에 남긴다. 범위 밖이라 넣지 않은 것은 제목에 "클립보드에 넣지 않음"을 붙인다(알림 센터의 [클립보드에 복사]로 넣을 수 있음).

### 6.3 표시

대시보드(이 PC 상태)에 한 줄:
- "휴대폰 바로 받기 · 지정한 사이트만 (threads.com 외 1) · Archiver 실행 중 · 오늘 3건 · 마지막 14:32"
- Archiver가 꺼져 있으면 주의 색으로 "Archiver가 꺼져 있어 받은 Threads 링크가 다운로드되지 않습니다". Threads가 범위에 없으면 Archiver 부분은 뺀다.
- Archiver 확인은 대시보드가 보일 때만 몇 초마다(M-13). 오늘 수·마지막 시각은 트레이 메모리(재시작하면 0).

## 7. 대가와 위험

- **다른 앱이 바로가기를 흉내 낼 수 있다.** 휴대폰의 아무 앱이나 `ClipShareActivity`를 PC 바로가기 id와 텍스트로 열 수 있고, Android에는 공유 시트에서 왔는지 믿을 만하게 확인할 방법이 없다(`getLaunchedFromUid`는 호출한 쪽이 동의할 때만 값을 준다). 줄이는 방법: 휴대폰 기본 꺼짐, PC 기본 범위는 지정한 사이트만, 범위 밖은 클립보드를 건드리지 않음, 1분 10번 제한. 남는 피해: PC 클립보드가 범위 안의 링크 하나로 바뀜(기본값이면 Threads 링크 → 공개 글 하나 다운로드). `모든 텍스트`를 고르면 임의의 텍스트가 들어갈 수 있다.
- **PC 클립보드를 덮어쓴다.** PC에서 복사해 둔 것이 바뀐다(Win+V 기록을 켰으면 거기 남음).
- **Threads 공유 시트**: Threads가 자기 시트를 먼저 띄우면 시스템 공유로 한 번 더 넘어가야 바로가기가 보일 수 있다.
- **같은 링크 다시**: Archiver는 한 번 실행하는 동안 같은 링크를 다시 알리지 않는다.

## 8. 검증 계획

- 단위: `quick` 봉인·파싱(양쪽), PC 범위 판정(사이트·하위 도메인·`http` 없는 토큰·4,096자), 1초 간격 큐, 보류 저장소(만료·건수·id 형식), Agent 응답(`quick`·`held`·`archiver`, PC 기기·`to`와 함께면 400), 휴대폰 범위 판정·1분 10번 제한·옛 PC 응답.
- 에뮬레이터: `am start -a android.intent.action.SEND -t text/plain --es android.intent.extra.TEXT … --es android.intent.extra.shortcut.ID …`로 공유 시트를 흉내 내어 바로 보내기·토스트·실패 알림을 본다.
- 실기기(S24): Threads 앱 공유 → 시스템 공유 → PC 바로가기 → Archiver 다운로드 시작까지.
