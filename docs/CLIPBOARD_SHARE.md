## 1. 요구와 성공 기준

요구(사용자): 클립보드 동기화. 이미지·텍스트 파일 교환도 되면 좋겠다. 먼저 어디까지 구현할 수 있는지 계획안을 본다.

**성공 기준**
- PC에서 복사한 텍스트를 휴대폰에서 바로 붙여 넣는다. 반대 방향도 된다.
- 휴대폰의 사진·파일을 PC로, PC의 파일을 휴대폰으로 두세 번 눌러 보낸다.
- 새 서버나 제3자 평문 경로를 두지 않는다. 지금 페어링과 경로(LAN·Tailscale·Cloudflare)를 그대로 쓴다.
- "보지 않을 때 PC 부담 0"(M-13)을 지킨다. 보내지 않는 동안 상주하는 일이 없다.

## 2. 한눈에: 어디까지 되나

| 무엇 | PC → 휴대폰 | 휴대폰 → PC | PC ↔ PC |
|---|---|---|---|
| 텍스트, **누를 때 보내기** | ✅ | ✅ | ✅ |
| 텍스트, **자동 동기화** | △ 앱을 열 때만 | ❌ Android가 막음 | ✅ 선택 기능 |
| 클립보드 이미지(캡처 등) | ✅ 파일로 받음. 휴대폰 클립보드에서 붙여넣기는 앱마다 다름 | ✅ PC 클립보드에 그림으로 넣음 | ✅ |
| 파일(사진·문서·여러 개) | ✅ 알림을 눌러 받기 | ✅ 공유 메뉴 | ✅ |
| 큰 파일(수백 MB 이상) | △ | △ | △ |

- **휴대폰 → PC 자동은 안 된다.** Android 10(API 29)부터 앱은 화면 맨 앞에서 입력 포커스를 가졌거나 기본 키보드일 때만 클립보드를 읽는다. 백그라운드에서 복사를 알아채려면 키보드 앱을 만들거나 접근성 서비스를 써야 하는데, 둘 다 개인정보·Play 정책 부담이 커서 하지 않는다. 대신 공유 메뉴와 빠른 설정 타일로 두 번 누르면 보내게 한다.
- **PC → 휴대폰 자동은 제한적이다.** 휴대폰은 서버가 아니라서 PC가 직접 연결하지 못한다(M-27). 백그라운드로 전하는 길은 푸시뿐이다. 그런데 ntfy.sh 하루 250건(M-21)을 알림과 나눠 쓰므로, 복사할 때마다 보내면 한도가 바닥난다. 그래서 기본은 누를 때 보내기다. 선택 기능으로 "앱을 열면 PC의 최근 클립보드 보기"를 둘 수 있다(4단계).
- **PC ↔ PC 자동은 된다.** 트레이가 Windows 클립보드 변경 이벤트를 받을 수 있고, PC끼리는 직접 연결하므로 한도도 없다. 다만 Windows 자체 클립보드 동기화(Win+V, Microsoft 계정)와 겹친다.
- **큰 파일**: LAN·Tailscale에서는 문제없다. Cloudflare 무료 요금제는 요청 본문을 100MB로 제한하므로 8MiB 조각으로 나눠 보낸다. Cloudflare 경로는 느리고 엣지에서 TLS가 풀린다(§4.6).

## 3. 지금 구조에서 확인한 사실

- Agent는 LocalSystem 서비스(세션 0)라서 사용자 클립보드에 닿지 못한다. 클립보드 읽기·쓰기는 사용자 세션의 트레이가 맡아야 한다. 트레이↔Agent는 `Homebase.MobileBridge` 파이프(4바이트 길이 + JSON)이고, 프레임은 최대 1MiB다(`MobileBridge.MaxFrameBytes`).
- Agent HTTP 서버(`MiniHttp`)는 본문을 메모리에 통째로 읽는다. 한도는 16KiB(`MaxBodyBytes`)이고, 예외는 `POST /api/v1/live-snapshot`의 1MiB 하나다. 이때도 토큰을 먼저 확인한 뒤에야 큰 본문을 읽는다. 동시 연결은 32개이고 요청마다 연결 하나다.
  → 텍스트는 같은 방식(경로별 한도, 인증 먼저)으로 된다. 파일은 본문을 디스크로 흘려 쓰고 흘려 읽는 처리가 새로 필요하다.
- 휴대폰으로 가는 백그라운드 경로는 UnifiedPush 하나다. 암호문은 4096바이트 이하(평문 JSON 약 3.9KB)이고, ntfy.sh 하루 250건은 휴대폰 한 대가 모든 PC와 나눠 쓴다. 모든 PC가 휴대폰 푸시 키를 함께 쓰므로, 한 PC가 다른 PC인 척하지 못하게 하려면 경로 푸시처럼 토큰 HMAC 서명이 필요하다(M-23).
- 앱은 `kind`가 `endpoints`가 아닌 푸시를 알림으로 읽고, `title`이 없으면 버린다(`PushReceiver`). 그래서 새 `kind`를 `title` 없이 보내면 옛 앱에는 아무것도 뜨지 않는다. 다만 PC는 받지 못하는 휴대폰을 대상에서 빼야 하므로, 휴대폰이 이 기능을 지원하는지 PC가 알아야 한다.
- 기기 그룹(M-47)에서는 모든 PC·휴대폰이 서로의 토큰을 가진다. 그래서 휴대폰→PC와 PC→PC 직접 요청은 지금도 된다. 푸시가 필요한 방향은 PC→휴대폰뿐이다.
- 트레이에는 Windows 클립보드 기록(Win+V)과 클라우드 동기화에서 내용을 빼는 코드가 이미 있다(`PhoneConnectPanel.CopySecret`: `CanIncludeInClipboardHistory`·`CanUploadToCloudClipboard` = 0, 클립보드가 바쁘면 재시도). 받은 민감한 텍스트를 넣을 때 이 코드를 그대로 쓴다.
- 앱 매니페스트에는 공유 받기(`ACTION_SEND`), 타일, 포그라운드 서비스가 없다. minSdk 26, targetSdk 36이다.
- 프로젝트 첫 원칙(`00_project_overview.md` §4.2)은 "clipboard 전체 감시"를 범위에서 뺐다. 설계 번들 TRAIN-D는 클립보드·파일을 KDE Connect 위에 두었지만(ADR-006), KDE 쪽은 착수 조건(실기기 프로토콜 고정)을 채우지 못했다. 그 뒤 기기 연동은 Homebase 앱으로 해 왔다(M-27~M-29, M-47).

## 4. 제안

### 4.1 기본 모델: 동기화보다 "보내기"

- 기본은 **사용자가 누를 때 한 번 보내기**다. 감시는 없다. 받는 쪽은 받은 텍스트를 바로 클립보드에 넣는다. 사용자에게는 "복사 → 보내기 → 붙여넣기"로 느껴진다.
- 자동 동기화는 되는 방향만 선택 기능으로 둔다(4단계, 기본 꺼짐).
- 근거: Android 제약, 푸시 한도, 그리고 "클립보드 감시 제외" 원칙과 맞는다. 1~3단계에는 감시 코드가 없다.

### 4.2 사용자 흐름

**PC**
- 트레이 메뉴 **보내기 ▸** [휴대폰·PC 이름들] / [모든 휴대폰]: 지금 클립보드를 보낸다. 텍스트, 그림, 탐색기에서 복사한 파일 목록을 모두 받는다.
- **파일 보내기…**(파일 고르기), Homebase 창의 기기 목록에 끌어다 놓기, 탐색기 **보내기 › Homebase**(SendTo 바로가기, 3단계).
- 단축키(선택, 기본 꺼짐): 마지막 대상에게 클립보드를 보낸다.
- 받으면 텍스트는 클립보드에 넣고 풍선 "Galaxy S24에서 받은 텍스트를 클립보드에 넣었습니다"를 띄운다. 그림은 클립보드에 넣고 `다운로드\Homebase`에도 저장한다. 파일은 `다운로드\Homebase`에 저장하고 풍선에 [열기] [폴더 열기]를 단다.

**휴대폰**
- 공유 메뉴의 **Homebase** → PC 고르기(마지막 대상이 맨 위). 텍스트·링크·사진·파일 여러 개를 보낼 수 있다.
- 빠른 설정 타일 **클립보드 → PC**: 누르면 투명 화면이 잠깐 떠서 클립보드를 읽고(포커스가 있어야 읽힌다) 마지막 PC로 보낸 뒤 닫힌다. Android 12 이상은 이때 "클립보드에서 붙여넣음" 안내를 띄운다.
- PC 카드 메뉴에 **클립보드 보내기 / 파일 보내기**를 둔다.
- 받으면 텍스트는 바로 휴대폰 클립보드에 들어간다(백그라운드 쓰기는 허용된다). 알림은 조용히 "집 PC에서 텍스트 — 복사됨"으로 뜬다. 이미지·파일은 알림 "집 PC에서 사진 2장 (4.1MB) [받기]"로 뜬다. 받은 사진은 `Pictures/Homebase`, 그 밖의 파일은 `Download/Homebase`에 두고 [열기] [공유]를 단다. 작은 파일(예: Wi-Fi에서 10MB 이하) 자동 받기는 선택이다.

### 4.3 프로토콜 (Mobile Protocol v1에 추가, `schema` 1 유지)

**텍스트**
- `POST /api/v1/clip`(Bearer) `{schema, id, text, sensitive?}`: 휴대폰이나 PC가 PC로 보낸다. 텍스트는 최대 256KiB이고 토큰을 확인한 뒤에 읽는다. 응답은 200 `{schema, accepted}`, 409 `no_user_session`(트레이 없음, 로그인한 사용자 없음), 413이다.
- PC → 휴대폰은 푸시 `{schema, kind: "clip", pcId, data, mac}`이다. 서명은 경로 푸시(M-23)와 같다. `data`는 `{schema, id, pcId, ts, size, text?, sensitive?}`다. 텍스트가 약 2KB(UTF-8)를 넘으면 `text`를 빼고 보낸다. 그러면 사용자가 알림을 누를 때 휴대폰이 `GET /api/v1/clip/<id>`로 받는다(PC 메모리에 10분 보관).
- 지원 여부: `POST /api/v1/push`에 `features: ["clip"]`을 더한다(1단계 구현). PC는 이 값이 있는 휴대폰만 대상 목록에 보인다.

**파일** (조각, 이어 보내기 가능)
- `POST /api/v1/transfers` `{schema, id, name, size, mime, sha256}` → `{schema, id, chunkBytes, received}`. 크기 한도와 디스크 여유는 여기서 먼저 확인한다.
- `PUT /api/v1/transfers/<id>?offset=<n>`: 원시 바이트 한 조각(8MiB 이하)을 디스크로 흘려 쓴다.
- `GET /api/v1/transfers/<id>` → `{received, state}`: 끊긴 뒤 어디서부터 이어 보낼지 알려 준다(Wi-Fi ↔ LTE 전환 등).
- `POST /api/v1/transfers/<id>/complete`: SHA-256을 확인한 뒤 받는 사용자(트레이)에게 넘긴다.
- PC → 휴대폰은 방향을 뒤집는다. PC가 파일을 24시간 보관하고 푸시 `{kind: "share", …}`(서명)로 알린다. 휴대폰은 `GET /api/v1/transfers/<id>/content`(Range로 이어받기)로 받은 뒤 `DELETE`한다. 받지 않으면 만료된다.
- 푸시가 없는 휴대폰은 앱을 열 때 `GET /api/v1/shares/pending`으로 받을 것을 확인한다.
- 새 픽스처는 `clip.v1.json`, `push-clip.v1.json`, `transfer.v1.json`, `push-share.v1.json`이다. 지금처럼 .NET과 Kotlin이 같은 파일을 검증한다.

### 4.4 PC 안: Agent ↔ 트레이

- **원칙: Agent(SYSTEM)는 사용자가 고른 경로를 열지 않고, 사용자 폴더에 쓰지도 않는다.** SYSTEM이 사용자 경로를 다루면, 정션이나 하드링크로 SYSTEM이 다른 파일을 읽거나 덮어쓰게 만드는 권한 상승 경로가 생긴다(설계 번들 R-04와 같은 종류).
- 보내기: 트레이가 사용자 권한으로 파일·클립보드를 읽어 바이트를 Agent에 흘려 넘긴다. Agent는 받은 바이트를 자기 폴더 `ProgramData\Homebase\transfers`(SYSTEM·Administrators 전용, M-32와 같은 방식)에 둔다.
- 받기: Agent가 받은 파일을 같은 폴더에 두고 트레이에 알린다. 트레이가 바이트를 읽어 `%USERPROFILE%\Downloads\Homebase\`에 쓴다.
- 바이트 통로: JSON 브리지에 base64를 싣지 않는다. 같은 ACL의 전용 파이프 `Homebase.Transfer`(4바이트 길이 + 원시 바이트)를 둔다.
- 새 브리지 연산: 트레이→Agent `share.targets`, `share.send {targets, kind, text?, sensitive?}`, `transfer.begin`·`transfer.cancel`. Agent→트레이 `clip.set {text, from, sensitive}`, `transfer.received {id, name, size, mime, from}`.
- 트레이가 없으면(로그인한 사용자 없음) 텍스트는 409로 거절한다. 파일은 Agent가 24시간 보관했다가 트레이가 붙으면 넘긴다. `mobile.userSid`가 정해져 있으면 그 사용자의 트레이에만 넘긴다.

### 4.5 받은 파일 안전

- **이름 정리**: 경로 구분자, `..`, 예약 이름(CON·NUL·COM1…), 끝의 점·공백, 제어 문자를 지운다. 확장자를 위장하는 **방향 바꿈 문자(U+202E 등)**도 지운다. 이름은 255자까지이고, 같은 이름이 있으면 `이름 (2).확장자`로 저장한다.
- **MOTW**: 받은 파일에 `Zone.Identifier`(ZoneId=3)를 붙인다. 그러면 실행 파일은 SmartScreen이, Office 문서는 보호된 보기가 경고한다.
- 받은 파일을 자동으로 열지 않는다.
- **한도**: 파일당 기본 2GiB(설정으로 변경). 남은 공간이 (파일 크기 + 2GiB)보다 작으면 507로 거절한다. 동시 전송은 4개까지, 보관 24시간이 지나면 정리한다.
- **휴대폰 저장**: API 29 이상은 MediaStore로 저장하므로 권한이 필요 없다. API 26~28은 앱 전용 폴더에 두고 [열기] [공유]만 단다(저장소 권한을 새로 요구하지 않는다).

### 4.6 개인정보·보안

- 내용(클립보드 텍스트, 파일 바이트)은 로그에 남기지 않는다. 알림 센터에 남긴다면 "Galaxy S24에서 사진 2장" 같은 메타데이터만 남긴다(선택).
  - v0.57.0(DECISIONS M-70)에서 사용자 요청으로 바뀌었다: 주고받은 클립보드 텍스트는 양쪽 알림 센터에 앞 2,000자까지 남는다. `sensitive`인 내용은 여전히 남기지 않는다.
- **비밀번호 관리자 표시를 지킨다.** Windows 클립보드에 `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0`, `CanUploadToCloudClipboard=0` 가운데 하나가 있으면 비밀번호 관리자가 넣은 내용으로 본다. 자동 동기화는 이런 내용을 건너뛴다. 누를 때 보내기는 "비밀번호 관리자가 복사한 내용입니다. 보낼까요?"를 묻고, 보내면 `sensitive: true`를 붙인다.
- 받는 쪽은 `sensitive`이면 PC에서는 Win+V 기록·클라우드 동기화에서 뺀다(기존 코드). 휴대폰에서는 `ClipDescription.EXTRA_IS_SENSITIVE`(API 33 이상)로 미리보기를 가린다. 알림에 본문을 싣지 않는다.
- **앱 수준 암호화(권장)**: Cloudflare 경로는 엣지에서 TLS가 풀리므로, 클립보드·파일 내용이 Cloudflare에서 평문이 된다. 지금의 스냅숏·중계 알림도 마찬가지다. 전송 본문을 조각마다 AES-GCM으로 한 번 더 암호화하면 경로와 상관없이 종단 암호화가 된다. 키는 기기 토큰의 SHA-256(양쪽이 이미 아는 값, M-23)에서 HKDF로 만든다. 의존성은 늘지 않는다(플랫폼 암호). 경로마다 다르게 하지 않고 항상 켜는 쪽을 권장한다.
- **받기 정책**: 그룹 기기에서 온 것은 묻지 않고 받는다(페어링 = 신뢰). 휴대폰을 잃어버리면 지금처럼 철회한다. 설정으로 "받을 때마다 묻기"를 둔다.
- 인터넷(Cloudflare)에 열린 API에 업로드 경로가 생긴다. 그래서 본문을 읽기 전에 인증하고, 한도와 속도 제한을 둔다. 보안 리뷰 대상이다.

### 4.7 하지 않는 것

- 휴대폰 → PC 자동 클립보드 감시: 키보드 앱이나 접근성 서비스가 필요하다.
- KDE Connect 호환: TRAIN-C 착수 조건을 채우지 못했고 GPL 경계도 있다. 그래서 ADR-006을 "공유·파일·클립보드도 Homebase 앱으로"로 개정한다.
- ntfy 첨부나 Telegram으로 파일 보내기: 제3자가 평문을 본다.
- 휴대폰에 서버 열기.
- 폴더째 보내기와 폴더 동기화. 파일 여러 개는 보낼 수 있다.
- 클립보드 이력 동기화. 마지막 하나만 다룬다.

## 5. 단계

| 단계 | 범위 | 규모 | 비고 |
|---|---|---|---|
| **1** 텍스트 보내기 | PC ↔ 휴대폰, PC → PC 텍스트(누를 때). 트레이 메뉴, 휴대폰 공유 메뉴(텍스트)·타일·PC 카드 메뉴, `POST /api/v1/clip`, 서명 푸시 `clip`, `features`, 민감 표시 | 중 (PR 1개) | 가장 체감이 크고 위험이 작다. 새 권한 없음 |
| **2a** 휴대폰 → PC 파일·이미지 | 공유 메뉴(모든 형식, 여러 개), 조각 전송 API, `MiniHttp` 스트리밍, 전송 폴더, `Homebase.Transfer` 파이프, 받은 파일 안전(§4.5), 받은 그림을 클립보드에 | 대 | 스트리밍 HTTP가 핵심 작업 |
| **2b** PC → 휴대폰·PC 파일·이미지 | 트레이 파일 보내기, 클립보드의 그림·파일 목록 보내기, 푸시 `share`, 휴대폰 받기·저장(MediaStore), 받기 진행 알림, PC → PC 파일 | 대 | 큰 파일을 화면 밖에서도 받으려면 포그라운드 서비스 필요(§6) |
| **3** 편의 | 탐색기 보내기, 끌어다 놓기, 휴대폰 공유 메뉴에 PC별 바로가기(Direct Share), 전송 목록(메타데이터), 휴대폰 ↔ 휴대폰(PC 중계) | 중 | 필요에 따라 고른다 |
| **4** 자동 동기화(선택) | PC ↔ PC 자동(되돌아오기 막기: 출처 id + 내용 해시), 앱을 열면 PC의 최근 클립보드 보기 | 소~중 | 기본 꺼짐. 이 단계만 "클립보드 감시 제외" 원칙을 좁게 번복 |

각 단계는 CHANGELOG 버전 하나와 랜딩 페이지 갱신을 같은 PR에서 한다(CLAUDE.md).

## 6. 대가와 위험

- **푸시 한도**: PC → 휴대폰 보내기 한 번이 푸시 1건이다(하루 250건을 알림과 나눠 씀).
- **Cloudflare 경로**: 100MB 요청 제한은 조각 전송으로 피한다. 느리므로 앱이 "Cloudflare 경로 — 느릴 수 있음"을 표시한다. 큰 파일을 상시 Cloudflare로 흘리는 사용은 권하지 않는다.
- **휴대폰 큰 파일**: 화면을 끄거나 앱을 나가도 전송이 이어지려면 포그라운드 서비스(`dataSync`)가 필요하다. 그러면 Play Console에 포그라운드 서비스 용도를 신고해야 하고, 설명과 영상을 요구받을 수 있다. 대안은 Android 14 이상의 사용자 시작 데이터 전송 잡이다. 2b에서 정한다.
- **이미지 붙여넣기 호환**: Android 클립보드의 이미지(content URI)를 붙여 넣을 수 있는 앱이 제한적이다. 그래서 휴대폰 쪽은 "사진으로 저장"을 기본으로 한다.
- **트레이 의존**: 아무도 로그인하지 않은 PC는 텍스트를 받지 못한다(409로 바로 알림).
- **버전**: PC와 앱이 모두 새 버전이어야 한다. 옛 PC는 404를 돌려주므로 앱이 "PC를 업데이트하세요"로 안내한다.
- **Play**: 데이터 보안 양식과 개인정보처리방침(`docs/privacy/`) 문구를 고쳐야 하는지 릴리스 전에 확인한다.

## 7. 검증 계획

- **단위**: 프로토콜 픽스처(.NET·Kotlin), 파일 이름 정리, 조각·이어 보내기·해시 불일치, 한도·디스크 여유, "인증 전에는 본문을 읽지 않음", 푸시 서명을 검증한다. 앱 수준 암호화는 기존 `push-message.v1.aes128gcm.txt`처럼 .NET이 만든 벡터를 Kotlin이 푸는 시험으로 확인한다.
- **통합**: 루프백 Agent 두 개(기존 방식)로 PC ↔ PC를 시험한다. 트레이에서는 STA 클립보드 넣기·읽기와 MOTW가 붙는지 확인한다.
- **실기기**: Android 10·13·14 이상에서 백그라운드 클립보드 쓰기, 타일 읽기, 공유 메뉴, MediaStore 저장, 진행 알림을 확인한다. LAN·Tailscale·Cloudflare(Quick Tunnel) 경로마다 200MB를 보내고, 중간에 끊은 뒤 이어 보내지는지 본다.

## 8. 결정이 필요한 것

1. **범위와 순서**: 1단계(텍스트)부터 시작하고 2단계는 2a/2b로 나눈다 — 권장.
2. **기본 모델**: 누를 때 보내기를 기본으로 하고, 자동 동기화는 4단계 선택 기능으로 둔다 — 권장. "클립보드 감시 제외" 원칙은 1~3단계에서 그대로 지킨다.
3. **받기 기본값**: 그룹 기기에서 온 것은 묻지 않고 받기(한도 안) — 권장. 아니면 매번 묻기.
4. **앱 수준 암호화**: 항상 켬(권장) / Cloudflare 경로만 / 안 함.
5. **파일 크기 한도 기본값**: 2GiB(권장).
6. **ADR-006 개정**: 클립보드·파일 공유를 KDE Connect(TRAIN-D)가 아니라 Homebase 앱·프로토콜로 한다.
7. **(2b) 휴대폰 포그라운드 서비스**: 쓰려면 Play 신고를 감수해야 한다. 2b를 시작할 때 다시 묻는다.
